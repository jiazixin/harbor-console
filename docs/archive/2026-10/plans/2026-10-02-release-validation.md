# 上线前全量验证与修复

**Goal:** 在保留当前目录迁移和可读性改动的基础上，发现并修复可复现缺陷，形成可追溯的发布检查结果。

**Architecture:** 保持 Go 单二进制、类型化 Harbor 网关与 React Web 边界。后端、前端及发布配置并行审查；修复以用户可观察行为和实际部署风险为依据，不为减少文件长度机械拆分。

**Tech Stack:** Go、React、TypeScript、Vite、Vitest、Playwright、Docker。

**本轮状态：** 可用环境内的检查、修复和复验已完成，最终证据与真实 Harbor 等待验收项见 [验收记录](../ACCEPTANCE.md)。

## 执行步骤

1. 读取目录规范、README、开发规范和构建配置；保留已有改动，记录本轮基线。
2. 执行前端格式、lint、类型、合同、组件测试、生产构建与依赖审计；审查异步取消、会话隔离、权限、失败和空状态。
3. 执行 Go 格式、模块一致性、vet、race、覆盖率和漏洞扫描；审查会话、请求边界、并发、资源限制和错误处理。具体缺陷先验证，再最小修复及回归。
4. 使用最终构建执行 Chromium、Firefox、WebKit 双语多视口路线与交互矩阵；实际查看代表性桌面、移动、暗色、弹窗截图，并检查性能与资源加载。
5. 用不含依赖、产物和本地配置的当前源码副本验证冻结安装、检查、构建和嵌入二进制启动；尝试容器构建和 smoke test。
6. 合并审查发现，重跑受影响检查；整理文档，移除或归档过期重复说明，校验链接和命令。
7. 在 `docs/ACCEPTANCE.md` 记录日期、当前工作区、命令、结果与未执行项。真实 Harbor 和容器条件缺失时如实记录，不借用历史通过结论。

## 交付标准

- 可复现的缺陷完成修复及相关验证。
- 构建、目录和文档使用唯一当前入口。
- UI 断言保留，不通过放宽测试隐藏问题。
- 本地配置、业务数据和此前未提交工作保持完整。
- 未完成的外部环境验证明确列为发布剩余条件。
