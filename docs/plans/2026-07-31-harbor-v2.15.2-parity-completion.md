# Harbor v2.15.2 等价补全 Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use executing-plans to implement this plan task-by-task.

**Goal:** 在不破坏类型化网关、多实例和单二进制架构的前提下，关闭 2026-07-31 审计确认的 Harbor v2.15.2 用户工作流缺口，并把 Swagger operation 覆盖从 181/203 提升到可独立验证的 203/203。

**Architecture:** 浏览器继续只调用命名 operation；Go 将每个 operation 固定映射到 Harbor v2.15.2 的 method/path/query/body，不增加任意路径代理。所有用户可见功能必须同时具备真实上游契约测试、可变 demo 数据、权限/不支持/错误状态和中英文界面；deprecated 接口仅做隔离的兼容映射，不替换稳定接口。

**Tech Stack:** Go 1.24 标准库、`gopkg.in/yaml.v3`、Harbor API v2.0、原生 HTML/CSS/JavaScript、Go `httptest`、Node `node:test`、内置 demo、浏览器桌面/移动验收。

---

## 执行规则

1. 先读 `docs/adr/0001-official-harbor-api-gateway.md` 和 `docs/harbor-v2.15.2-parity-audit.md`。
2. 在独立 `codex/...` 分支或 worktree 中执行；开始前记录 `git status --short`，不得覆盖用户已有改动。
3. 严格按 Task 顺序。每个 Task 都执行“失败测试 -> 最小实现 -> focused test -> 全量回归 -> 单独 commit”。
4. Go API 变更必须同时修改 `control.go`、`demo_control.go` 和 `main_test.go`；只改前端或只改 demo 不算完成。
5. 新增 UI 字符串必须同时验证简体中文和英文。不得依赖运行时 DOM 文本替换来修复复合动态文本；优先在渲染函数中使用明确的翻译 key。
6. 每个可选模块分别处理 `403`、`404` 和其他错误：`403` 显示权限不足，`404` 显示当前实例不支持，其他错误显示可重试状态。不能把错误渲染成空列表。
7. 不得实现任意 Harbor URL/method 代理，不得在浏览器存储 Basic/OIDC 凭据，不得把 upstream cookie、Authorization 或内部配置写入日志。
8. Task 11 的原生登录需要架构选择，执行模型不得自行选择或伪造完成；其余 Task 不应等待该选择。
