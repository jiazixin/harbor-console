# 1.0 上线前最终检查

**目标：** 在真实 Harbor 上完成整体功能与 UI 检查，统一视觉与交互，修复发现的缺陷，并把代码与文档整理为可长期维护的标准形态。

**范围：** 保持 Go 单二进制、类型化 Harbor 网关与 React Web 的既有边界，不改变配置协议与部署方式。

**本轮状态：** 已完成；证据与剩余条件见 [验收记录](../ACCEPTANCE.md)，改动见 [变更记录](../CHANGELOG.md)。

## 执行步骤

1. 读取目录规范、README 与开发文档；保留工作区已有改动。
2. 对真实 Harbor（测试专用实例）比对 API 合同，逐域执行创建、修改、删除与回读；用浏览器检查中英文、亮暗色与移动端界面。
3. 统一共享样式与组件：提示、表格列对齐、执行详情、加载指示、筛选表单与弹窗结构。
4. 拆分职责过多的页面与弹窗，把数据加载、路由解析与展示分开；补齐英文翻译并用合同测试防止回退。
5. 执行全部本地检查、依赖与漏洞扫描、三引擎浏览器矩阵，以及最终构建对真实 Harbor 的回归。
6. 更新当前文档，归档上一轮验收与计划。

## 完成标准

- 发现的缺陷已修复并有对应测试或真实环境回归证据。
- 不放宽既有断言；新增的列对齐与翻译覆盖检查进入常规测试。
- 未能在当前环境验证的项目在验收记录中明确列出。
