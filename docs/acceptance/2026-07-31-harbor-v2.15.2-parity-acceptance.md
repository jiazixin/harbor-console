# Harbor v2.15.2 等价验收计划

**用途：** 由未参与实现的高能力模型执行。

**验收基线：** Harbor v2.15.2 官方 Swagger 与 Portal 源码。

**原则：** 不信任实现模型的完成声明、覆盖数字或截图；所有关键结论必须独立复现。

## 1. 验收结论必须分开报告

最终不得只给一个模糊的“通过”。必须分别给出：

| Gate | 可能结论 | 通过条件 |
| --- | --- | --- |
| Regression | PASS/FAIL | 原有核心工作流和全部自动检查无回归 |
| Portal workflows | PASS/FAIL/BLOCKED | 审计中用户可见缺口全部在真实 Harbor 上闭环 |
| Stable API | PASS/FAIL | 所有非 deprecated operation 类型化映射正确 |
| Full Swagger | PASS/FAIL | 独立确认 203/203，含 deprecated 兼容 operation |
| Native login | PASS/FAIL/BLOCKED/NOT IMPLEMENTED | 选定架构的 OIDC/onboarding/session 流程真实通过 |
| Overall release | ACCEPTED/REJECTED/PROVISIONAL | 无 P0/P1，且要求范围内的 Gate 全部 PASS |

如果没有真实 Harbor v2.15.2 环境，Portal workflows 和 Native login 最多为 `BLOCKED`，Overall 只能是 `PROVISIONAL`，不能是 `ACCEPTED`。

## 6. 独立 API 覆盖复核

不要只相信 `parity_test.go`。验收者需检查：

1. fixture 来源是官方 Swagger，不是 `controlSpecs`。
2. test 展开每个 spec 的全部 method，不是只统计 spec 数量。
3. path placeholder 归一化只允许名称差异，例如 `{project}` 对 `{project_name_or_id}`；不能把不同层级或不同资源误归一化。
4. 五个直接映射确实向对应官方 API 发请求，不是本地静态响应。
5. HEAD 与 GET 分开计数，deprecated operation 没有被稳定 operation 冒名顶替。
6. 每个 write operation 仍具备 body size、allowed fields、type/range 和同源校验。
7. 每个 portal operation 有真实前端消费者；API-only/deprecated 可以没有页面，但分类必须诚实。

对 22 个原始 missing operation 逐项填表：

| Method/path | control operation | upstream contract test | demo | UI/分类 | PASS/FAIL |
| --- | --- | --- | --- | --- | --- |

任意一项 method/path 错误、无契约测试或用任意代理代替，Stable/Full Swagger Gate 为 FAIL。

## 8. 用户工作流验收

### A. Retention 与不可变规则

准备三条真实规则：

1. `repoMatches` + `matches`
2. `repoExcludes` + `excludes`
3. `extras.untagged=true`

验收步骤：

1. 页面正确回填 template、repository decoration、tag decoration、pattern 和 untagged。
2. 只修改数量/天数并保存。
3. 直接 GET 官方 API，对保存前后 JSON 做语义比较。
4. 除修改字段、更新时间和 Harbor 服务端生成字段外，其余字段必须相同。
5. metadata 403/404 时旧规则仍可读，但危险编辑不可执行。
6. 非法 decoration、空 pattern 和非布尔 untagged 在控制台被拒绝且 Harbor 未收到请求。

任何 include/exclude 翻转或 `extras` 丢失为 P0，Overall 直接 REJECTED。

### B. 项目成员搜索

使用非系统管理员的项目管理员账号：

1. 输入普通用户名片段，确认请求 `/users/search`，不是 `/users`。
2. 快速输入三个查询，只有最新结果留在界面。
3. 已有成员不出现在可选结果或明确禁用。
4. 输入用户组片段，确认非 LDAP 模式请求 `/usergroups/search`，不是 `/usergroups`。
5. 成功添加用户和用户组；重复添加显示 409 语义提示。
6. LDAP 模式仍走 LDAP group search。

普通项目管理员收到不必要 403 为 P1。

### C. 项目审计

1. 有权限项目显示审计 tab，无权限项目不发审计请求。
2. 默认请求项目 `/auditlog-exts`，验证用户、资源、事件、结果、时间、排序和分页。
3. 切换项目时旧响应不会污染新页面。
4. 模拟扩展接口 404 才降级 `/logs`，并显示 legacy 标识。
5. 403 显示权限不足，5xx 显示重试，不能显示“暂无记录”。

### D. 内容信任与 Proxy Cache

使用普通项目和 Proxy Cache 项目分别测试：

1. Notary 与 Cosign 开关独立回填和更新，API 中保持字符串 boolean。
2. 更新一个普通设置不会清除两个信任字段或未知 metadata。
3. 有权限管理员可修改带宽和最大连接数，单位转换准确；`-1` 往返保持不限制。
4. registry 只有官方允许且权限满足时可编辑。
5. 普通项目不发送 proxy-only metadata。
6. 删除项目先调用 `_deletable`；false/message 会阻止 DELETE。

### E. Artifact metadata 与命令

准备 IMAGE、CHART、Cosign signed、Notation signed、unsigned、含 icon、无 icon、四个 annotations 的真实 Artifact：

1. icon MIME/base64 正确显示；404 只降级该图标；SVG/HTML payload 不渲染。
2. Signed、Unsigned、Unknown 区分正确；网络失败不得显示 Unsigned。
3. 只有官方签名 accessory/referrer 被识别为签名。
4. 列表 annotations 可扫描，详情能看到全部 key/value，不只前三条。
5. IMAGE tag/digest 命令正确。
6. CHART tag 显示 `helm pull oci://... --version ...`，不出现 Docker pull。
7. CHART digest-only 不伪造 tag 命令。
8. repository 已含 project 前缀时路径不重复。

### F. 中英文

英文模式遍历：登录、概览、项目全部 tab、Artifact、复制、Registry、P2P、安全、用户、用户组、扫描器、维护、配置。

- 可见系统 UI 不出现中文残留。
- 用户输入、资源名、日志和 Harbor 原始错误允许中文，不得被翻译器篡改。
- 特别复核 `Users are managed by OIDC`、Policy ID 两种排序和 Oldest updated。
- 切回中文后不存在 translation key、英文占位或布局错位。

## 9. API-only 与 deprecated 验收

通过 `httptest` 契约测试和真实 Harbor 请求分别验证：

- `HEAD /projects` 没有 body，状态码/响应头正确。
- all repositories 和 project artifacts 的 query、分页与 `X-Total-Count` 正确。
- project member detail 路径和权限正确。
- project metadata CRUD 完整往返，meta name 不能进行路径穿越。
- `/internalconfig` 仅系统管理员可用，响应或日志不泄露 secret。
- `/ping` 与本地 `/health` 语义分离。
- deprecated operation 命名和代码注释明确，除项目审计 404 fallback 外不被新 UI 使用。

对 deprecated 接口仅验证兼容映射，不要求新增用户入口。

## 10. 原生登录验收

先读取 `docs/adr/0002-harbor-native-authentication.md`：

- 文件不存在、状态未接受或未选择实现方案：Native login = `NOT IMPLEMENTED/BLOCKED`。
- 仅提供“打开 Harbor”链接、仍要求用户粘贴 CLI Secret：不能判 PASS。
- 声称完成时，至少在真实 DB Auth 和 OIDC Harbor 环境验证 login、callback/onboarding、刷新、logout、session expiry、多实例边界和失败恢复。
- 检查 state、nonce、PKCE（若适用）、redirect allowlist、HttpOnly/Secure/SameSite、CSRF、session fixation 和日志脱敏。
- 浏览器存储与 Network URL 中不得出现 token/password/CLI Secret。

Native login 不属于 203 个 Swagger operation，因此 Swagger PASS 不能覆盖本 Gate。

## 11. 安全和可靠性回归

至少复核：

- 路径参数编码：项目名、嵌套 repository、digest、metadata name
- 未知 query/body field 被拒绝
- 请求体 1 MiB、响应 8 MiB 限制仍有效
- 写操作同源校验和会话要求仍有效
- 上游 redirect 仍限制同协议同主机和次数
- Artifact icon 禁止可执行内容
- 日志以 text 渲染，不插入 HTML
- 搜索与图标并发有界，路由切换后过期响应被忽略
- 两个实例的 icon cache、成员候选、权限和 session 不串数据
- 危险操作有资源全名、确认和忙碌态，不可重复提交

发现凭据泄露、任意代理、规则语义破坏或跨实例数据污染均为 P0。

## 12. 缺陷等级与退出规则

| 等级 | 定义 | 处理 |
| --- | --- | --- |
| P0 | 凭据/权限泄露、任意代理、破坏规则语义、错误删除、跨实例串数据 | 立即停止，Overall REJECTED |
| P1 | 核心工作流缺失、错误 API 导致 403、设置无法保存、错误 Artifact 命令、Swagger 非 203/203 | 对应 Gate FAIL，Overall REJECTED |
| P2 | 部分字段/状态/移动端交互不完整但有安全替代路径 | 记录并要求修复后复验 |
| P3 | 文案、轻微布局或非阻塞一致性问题 | 可有条件接受，但必须列出 |

修复后只重测失败项不足以签字。必须先复现修复，再从第 5 节开始重跑全部自动化和相关用户工作流。
